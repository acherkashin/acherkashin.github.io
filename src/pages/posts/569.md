**Почему к настройке VPS нельзя относиться легкомысленно**

Вчера мне пришло письмо счастья от FirstVDS. У провайдера нашли уязвимость в ПО виртуализации, и несколько часов файлы на двух моих VPS теоретически могли читать посторонние.

Я пошёл разбираться. Сразу завершил активные сессии Codex, отозвал deployment key в GitHub, проверил пользователей, SSH-ключи и успешные входы.

Но вот что меня удивило: я посмотрел попытки подключения по SSH к своему VPS за указанный в письме период — их были сотни. В этом промежутке ни одна из них не была успешной. Вот несколько строк:
```
12:27 … authenticating user root 144.225… [preauth]
12:31 … Invalid user postgres from 193.46…
12:31 … Invalid user admin from 206.189…
12:33 … Invalid user hadoop from 144.225…
12:42 … Invalid user ubuntu from 201.184…
```

Я сперва испугался, потом поискал, и оказалось, что такие попытки идут постоянно. Боты сканируют публичные IP и пытаются брутфорсить доступные серверы.

С уязвимостью FirstVDS они, судя по всему, не связаны: у провайдера была проблема в системе виртуализации.

Раньше я относился очень легкомысленно к настройке VPS. Но теперь буду более осторожным. Хотя именно в этот раз я немного заморочился с настройкой:
- отключил вход по паролю через ssh
- закрыл вход под рутом через ssh
- закрыл лишние порты
- создал отдельного пользователя для гермеса

Но, как видим, это тоже не всегда помогает. Но, в любом случае, не пренебрегайте настройкой VPS.
Как минимум всегда отключайте вход по паролю, под рутом и закрывайте лишние порты.
